# Skill: Documentation Update

## Purpose
Update `PROJECT_STATE.md`, `HANDOFF.md`, and `NEXT_TASK.md` to reflect completed work, per `docs/ENGINEERING_RULES.md`.

## Responsibilities
- Record what was completed this sprint/session.
- Record current repository status and known issues.
- Record the next assigned feature and its acceptance criteria.

## Inputs
- The completed, verified feature or task
- Current contents of `PROJECT_STATE.md`, `HANDOFF.md`, `NEXT_TASK.md`

## Outputs
- Updated `PROJECT_STATE.md`, `HANDOFF.md`, and/or `NEXT_TASK.md`

## Success Criteria
- Documentation accurately reflects the repository's actual state after the update.
- Only the sections relevant to the completed work change.

## Rules
- Documentation changes require explicit approval or an explicit task requirement (per `docs/ENGINEERING_RULES.md`).
- Never rewrite `VISION.md` — it is constitutional.
- Never invent roadmap items or features not already approved.

## When NOT to Use
- Before a feature is actually complete and verified.
- For architecture specs under `specs/` — those need Chief Systems Architect approval.
